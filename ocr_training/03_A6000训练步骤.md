# A6000 远程训练步骤（交技术人员）

## 已核实的环境与限制

2026-10-19 只读检查：远程 RTX A6000 总计 49140 MiB，OCR 进程占用约 40216 MiB，空闲约 7708 MiB；PaddleOCR 3.7.0、PaddleX 3.7.2、Paddle GPU 3.3.0，运行 PaddleOCR-VL-1.6 + PP-DocLayoutV3。模型缓存位于 `/home/aiit/.paddlex/official_models/PaddleOCR-VL-1.6`。当前推理环境未发现 ERNIEKit / PaddleFormers 元数据。

这些是检查时的状态，不是显存泄漏或训练显存需求证明。不能在当前仅余约 7.5GiB 时直接并行训练。使用另一块 GPU，或在用户安排的维护窗口暂停服务，训练后按原启动方式恢复。不要直接 kill 正在处理档案的进程。

本包没有安装任何远程依赖、重启服务、上传档案或启动训练。完整环境记录和两份推理候选 YAML 另见项目 `outputs/ocr-a6000-plan-20261019/`。

## 1. 数据与标注

先使用真实试标包统一 10 个区域，再完成 30–50 页基线。后续可扩大到多卷 1000–3000 区域作为试验起点，并非官方最低门槛。保留未参与训练的卷册。

`export_dataset.py --check-only` 检查表格、图片哈希和独立复核，不会把 draft/uncertain 自动升级为真值。正式导出只接收 approved，且独立标注人与复核人必须不同。不要为了运行训练而填写虚假 approved。

## 2. 导出与传输

先在本地完成 README 中的检查与正式导出。导出目录包含 train.jsonl、validation.jsonl、test.jsonl、images/ 和审计 manifest。correction-pairs 文件仅是“原始 OCR → 人工转录”的配对，不是已训练的校正模型。

把 `ocr_training/` 工具、选定的数据集目录传到服务器的独立工作目录，例如 `/home/aiit/ocr-training/history/`。只传本次授权的数据，不上传密钥、数据库备份或整个原始档案库。整个目录必须一起传输，JSONL 使用相对 image_url。

## 3. 独立训练环境

不要修改现有 `/home/aiit/anaconda3/envs/paddle` 推理环境。按锁定版本的官方 ERNIEKit 文档在独立容器或 Conda 环境安装，记录 Git commit、Paddle/CUDA、模型文件 SHA256 和数据集 manifest。安装前核对 RTX A6000、驱动与所选 CUDA/Paddle 镜像组合。

官方详细教程与参考配置主要针对初代 0.9B，而本服务器为 1.6。必须先验证 1.6 的模型类、分词器、视觉处理器、权重加载和导出支持，不能仅改模型路径就声称兼容。也不假设 LoRA/QLoRA 可以直接工作。

官方参考：

- [PaddleOCR-VL 使用与微调说明](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/PaddleOCR-VL.html)
- [ERNIEKit SFT 教程，release/v1.5](https://github.com/PaddlePaddle/ERNIE/blob/release/v1.5/docs/paddleocr_vl_sft.md)
- [Full SFT 参考配置](https://github.com/PaddlePaddle/ERNIE/blob/release/v1.5/examples/configs/PaddleOCR-VL/sft/run_ocr_vl_sft_16k.yaml)

参考 YAML 需与实际训练框架版本匹配；旧配置的兼容性未实测，不建议在生产环境直接 pip upgrade。可以使用下列命令获取“参考文件”，但这不等同于装好或验证了训练框架：

```sh
mkdir -p /home/aiit/ocr-training/history/reference
curl -fL https://raw.githubusercontent.com/PaddlePaddle/ERNIE/release/v1.5/examples/configs/PaddleOCR-VL/sft/run_ocr_vl_sft_16k.yaml \
  -o /home/aiit/ocr-training/history/reference/run_ocr_vl_sft_16k.yaml
```

## 4. 生成小规模配置（不会启动训练）

假定工具放在 `/home/aiit/ocr-training/history/ocr_training`，导出数据在 `/home/aiit/ocr-training/history/datasets/history-v1`，技术人员已建立独立训练环境：

```sh
python /home/aiit/ocr-training/history/ocr_training/scripts/build_training_config.py \
  --reference /home/aiit/ocr-training/history/reference/run_ocr_vl_sft_16k.yaml \
  --dataset /home/aiit/ocr-training/history/datasets/history-v1 \
  --model-dir /home/aiit/.paddlex/official_models/PaddleOCR-VL-1.6 \
  --output /home/aiit/ocr-training/history/runs/history-smoke.yaml \
  --steps 10
```

生成 Full SFT 候选：batch_size=1、packing_size=1、梯度累积=8、max_seq_len=4096、bf16、重计算、学习率 5e-6。它只是起始试验配置，不承诺显存足够或 1.6 可直接训练。

先实际调用目标版本的 processor 检查“图像 token + 指令 + 正确转录”的长度和标签掩码。不能只看文本字符数；不能截断正确转录来强行塞进 4096。过长区域应重新拆图和复核。在不改变测试集的前提下逐步调整序列与图像预算。

## 5. 冒烟训练和保存重载

**仅在维护窗口或另一块空闲 GPU、数据审核与版本兼容检查完成后运行：**

```sh
cd /home/aiit/ocr-training/history/datasets/history-v1
CUDA_VISIBLE_DEVICES=0 erniekit train /home/aiit/ocr-training/history/runs/history-smoke.yaml
```

必须在数据集目录运行，才能解析相对 images/ 路径。若训练框架版本的 CLI 与官方参考不同，按该版本文档调整，不混用另一套 CLI 标志。

检查：loss 非空且有限；没有被截掉的目标；GPU 峰值；10 步结束能保存 checkpoint；用独立推理进程重新加载，并对固定区域图推理。检查 token/processor、chat_template.jinja、inference.yml 等配套文件，不只检查 safetensors 存在。

成功保存和重载不是准确率改善证明。若不兼容或 OOM，停止试验并保留日志，不回退覆盖线上权重。不要自动改用初代模型替换当前 1.6。

## 6. 正式试验与发布

根据审核样本数和有效 batch 计算步数，不能照搬官方示例的 926 步。先少量轮次，用验证卷选择 checkpoint，最终只在保留测试卷评一次。训练 loss 不能作为历史准确率指标。

分别报告：基座/候选 OCR CER、校正后 CER、人名地名及数字准确率、逐段退化率、漏行与阅读顺序、峰值显存、每页耗时。近似重复页和同一书写者关联仍需人工排查。

项目已有 `backend/scripts/evaluate_ocr_quality.py`，需要人工 reference 和实际生成的 raw/corrected 预测 JSONL；不能把 reference 复制到 corrected 冒充测试。中文主要看 CER，空白分词 WER 不当作中文词级指标。

通过离线评估后，先试运行完整 PP-DocLayoutV3 + VL 流水线，再决定上线；自定义权重保存在新目录，不覆盖官方缓存。保留原启动方式、配置和回滚权重。线上切换前确认无运行任务。

## 7. 后校正模型单独训练

OCR 图像 SFT 与“原始 OCR 文本 → 人工忠实转录”是两项任务。后者要混入原文已正确、目标保持不变的样本；不要混入现代英语改写或中文翻译。先评估本轮通用提示＋每卷配置，再决定是否需要训练专门的校正模型。
