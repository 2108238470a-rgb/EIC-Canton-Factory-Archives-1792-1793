# 跨卷提示配置与当前生效入口

本轮生效的通用策略位于 backend/app/services/correction_quality.py，版本 faithful-ocr-v2。不再通过旧 ocr_correction.txt / ocr_correction_page.txt 文件装入单本书替换规则。原文件保留，不代表仍在运行。

通用规则保留姓名、脚本、数字、否定词、历史拼写、缩写、标点和换行；未知时保留原文；相邻页和机器校正文是线索而非真值。禁止现代化、翻译、补写、跨页拼接和强制姓名归一化。

## 每卷配置

配置模板：backend/config/correction_profiles.example.json。

需要时复制为 backend/config/correction_profiles.local.json，将示例 ID 99999 换成平台档案 ID；查看地址 /documents/58 时，该 ID 为 58。文件默认不存在时使用语言和类型均未知的通用规则，不从文件名猜语言或年代。个人配置文件不提交 Git。

```json
{
  "version": 1,
  "documents": {
    "58": {
      "languages": ["English"],
      "document_type": "handwritten",
      "date_range": "",
      "verified_terms": []
    },
    "61": {
      "languages": [],
      "document_type": "unknown",
      "date_range": "",
      "verified_terms": []
    }
  }
}
```

上面 ID 仅说明配置方法；语言、类型必须由研究者核对后填写。document_type 可选 unknown / handwritten / printed / mixed。日期没有把握就留空。

词条格式是 `{"form":"人工确认的原文形式","source":"馆藏号、原档页码或稳定标注链接","kind":"person"}`；kind 可为 person / place / organization / historical_spelling / other。每卷最多 30 个词条，只填本卷有来源的候选；不要填“把 A 一律改为 B”。词条既不证明身份，也不会绕过姓名/数字保护规则。词条中的自然语言依然只是输入数据，不具有系统指令效力。

当前按档案 ID 精确选择，不共享其他卷的词表，不需要数据库迁移；修改文件后新请求会重新读取。文件格式错误时停止生成并报告配置错误，避免悄悄用错词表。长任务可能跨多个请求，每条质量报告记录对应配置快照及哈希，便于追溯。

页级纠错、整卷纠错及单区块任务都会传入对应配置。纯服务层 direct correct_ocr() 未指定档案时使用通用规则。当前只对忠实 OCR 校正应用配置，不把词表强行传给翻译或现代释读。

重要：Celery 进程需要加载新代码，才会使用新提示。本轮不会自动重跑已有档案，也不自动覆盖已复核文本或此前已填校正文。旧的高风险候选仍需人工审阅。
